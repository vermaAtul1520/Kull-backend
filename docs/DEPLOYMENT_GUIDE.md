# KULL Backend - AWS Deployment Guide

## Prerequisites

Before deploying, ensure you have:
- AWS CLI installed and configured
- SAM CLI installed
- An AWS account with appropriate permissions

---

## Environment Variables to Configure

### 🔐 Required Secrets (Store in AWS Secrets Manager)

| Variable | Description | How to Get |
|----------|-------------|------------|
| `JWT_SECRET` | Secret key for JWT token signing | Generate: `openssl rand -hex 32` |
| `SENDGRID_API_KEY` | SendGrid API key for emails | [SendGrid Dashboard](https://app.sendgrid.com/settings/api_keys) |
| `MONGO_URI` (optional) | MongoDB connection string | MongoDB Atlas dashboard → Connect → Drivers |

### 📦 Required Parameters (Store in AWS SSM Parameter Store)

| Variable | Description | Example Value |
|----------|-------------|---------------|
| `SUPER_ADMIN_EMAIL` | Admin email address | `admin@yourcompany.com` |

### 🔄 Auto-Generated by SAM Template

These are **automatically set** by the SAM template - no action needed:

| Variable | Description |
|----------|-------------|
| `NODE_ENV` | Set to `production` |
| `DB_TYPE` | Set to `dynamodb` |
| `DYNAMODB_TABLE_PREFIX` | Set to `kull-{stage}-` |
| `AWS_DYNAMODB_REGION` | Auto-detected from deployment region |
| `S3_BUCKET_NAME` | Auto-created S3 bucket name |
| `AWS_S3_REGION` | Auto-detected from deployment region |

## Step-by-Step Deployment

### Step 1: Store Secrets in AWS

Run these AWS CLI commands (replace values with your actual secrets):

```bash
# Create secrets in AWS Secrets Manager
# Replace 'YOUR_JWT_SECRET' with a secure random string
aws secretsmanager create-secret \
  --name kull/prod/JWT_SECRET \
  --secret-string "YOUR_JWT_SECRET_HERE" \
  --region ap-south-1

# Replace with your SendGrid API key
aws secretsmanager create-secret \
  --name kull/prod/SENDGRID_API_KEY \
  --secret-string "YOUR_SENDGRID_API_KEY_HERE" \
  --region ap-south-1

# Optional: For MongoDB mode (if switching from DynamoDB)
# aws secretsmanager create-secret \
#   --name kull/prod/MONGO_URI \
#   --secret-string "mongodb+srv://user:pass@cluster.mongodb.net/kull" \
#   --region ap-south-1
```

### Step 2: Store Parameters in SSM

```bash
# Store super admin email
aws ssm put-parameter \
  --name /kull/prod/SUPER_ADMIN_EMAIL \
  --value "admin@yourdomain.com" \
  --type String \
  --region ap-south-1
```

### Step 3: Build and Deploy

```bash
# Build the SAM application
npm run sam:build

# Deploy to staging first
npm run sam:deploy:staging

# After testing, deploy to production
npm run sam:deploy:prod
```

### Step 4: Get Your API URL

After deployment, get your API endpoint:

```bash
aws cloudformation describe-stacks \
  --stack-name kull-backend-prod \
  --query "Stacks[0].Outputs[?OutputKey=='ApiEndpoint'].OutputValue" \
  --output text
```

## Data Migration (After Deployment)

Once deployed, migrate your MongoDB data to DynamoDB:

```bash
# Preview what will be migrated
npm run db:migrate:dry-run

# Run the actual migration
npm run db:migrate
```

## Troubleshooting

### "Secret not found" Error
Make sure secrets are created with exact names matching the template:
- `kull/prod/JWT_SECRET`
- `kull/prod/SENDGRID_API_KEY`

### "Parameter not found" Error
Make sure SSM parameters use forward slash prefix:
- `/kull/prod/SUPER_ADMIN_EMAIL`

### AWS Region
Default region is `ap-south-1` (Mumbai). To change:
1. Update `samconfig.toml`
2. Recreate secrets/parameters in new region
